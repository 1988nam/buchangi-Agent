# 부챙이 자동매매 전략 설계 V1

> 흰챙이 가족의 **국내주식 자동매매** 에이전트. 투챙이(투자 분석)의 KIS 연동·3단계 필터를
> 이어받아, 사람이 버튼을 누르지 않아도 **스스로 매수/매도**한다.
> **모의투자(VTS) 우선 · dry-run 기본 ON** — 검증된 뒤에만 실거래로 전환한다.

---

## 0. 안전 원칙 (먼저 읽을 것)

자동매매는 **실제 돈과 법적 책임**이 걸린 행위다. 부챙이는 다음을 강제한다.

1. **모의투자(VTS) 기본** — `tradeEnv: "mock"`. 실거래(`real`) 전환은 대시보드에서 다단계 확인을 거쳐야 한다.
2. **Dry-run 기본 ON** — 켜져 있으면 주문을 **전송하지 않고** "샀을 것/팔았을 것"만 로그에 남긴다. 전략 검증용.
3. **Kill-switch** — 한 번 누르면 모든 신규 주문 중단(보유분 청산 로직만 선택적으로 유지).
4. **일일 한도** — 일일 최대 손실액·최대 주문 횟수 초과 시 그날은 자동 정지.
5. **화이트리스트 전용** — 워치리스트에 등록한 종목만 거래. 임의 종목 자동 매수 금지.
6. **종목당 비중 한도** — 한 종목이 계좌의 N%를 넘기지 않도록 매수 차단.
7. **현금 비중 하한** — 안전자산(현금) 비중을 항상 일정 % 이상 유지.

손실에 대한 책임은 운용자(사용자) 본인에게 있다. 이 도구는 보조 수단이다.

## 1. 실행 모델

- **엔진**: Cloudflare Worker + **Cron Trigger**. 브라우저와 무관하게 정해진 주기로 깨어나 평가→주문한다.
- **주기**: 장중(09:00~15:20 KST)에 약 5분 간격(`*/5 * * * *`, UTC 기준 cron은 KST-9h 보정). 워커가 한 번 깰 때마다 1 사이클.
- **상태**: Cloudflare KV에 설정/워치리스트/포지션 상태/일일 카운터/매매 로그/kill-switch를 저장. 사이클 간 상태 유지.
- **대시보드**: 정적 페이지(브라우저)에서 워커의 HTTP API를 호출해 설정·한도를 바꾸고 로그·포지션을 본다. **거래 자체는 대시보드가 하지 않는다**(워커가 한다).

```
[Cron Tick] → 워커 깨어남
   1) 게이트 검사 (kill-switch / 거래시간 / 일일한도)         ← 3단계 ③
   2) KIS 토큰 발급·갱신
   3) 잔고·보유종목 조회 (현금, 포지션, 평가손익)
   4) 시장 추세 확인 (코스피 MA)                              ← 3단계 ①
   5) 워치리스트 각 종목:
        - 일봉(OHLC) + 현재가 조회
        - 청산 신호? (익절/손절)  → 매도
        - 진입 신호? (변동성 돌파 ∧ 추세 ∧ 게이트 통과) → 매수  ← 3단계 ②
   6) 결정/주문을 KV 로그에 기록 (dry-run이면 주문 생략)
```

## 2. 3단계 필터 = GO / NO-GO 게이트

투챙이 `strategy_guide.md`의 3단계 필터를 **자동매매용 게이트**로 재해석한다.
(투챙이의 원본은 장기 자산배분 관점 — 여기서는 "지금 매수해도 되는가"의 관문으로 변환)

| 단계 | 원래 의미 (투챙이) | 부챙이 자동매매 게이트 |
|---|---|---|
| **①전략 부합성** | IRP보다 ISA 우선, 지수형 코어 복리 | **시장 추세 게이트**: 코스피 지수가 N일 이동평균 **위**일 때만 신규 매수 허용. 아래면 관망(현금 유지). |
| **②부채 허들 / 비중** | 대출금리(3.67%)보다 낮은 기대수익이면 상환 우선 | **포트폴리오 게이트**: 화이트리스트 종목만 + 현금 비중 하한(예 30%) 유지 + 종목당 비중 한도. |
| **③생애주기 / 리스크** | 출산·과세 대비 유동성 | **리스크 게이트**: kill-switch OFF + 거래시간 + 일일 손실/주문 한도 미초과. |

세 게이트가 **모두 통과**해야 신규 매수가 일어난다. 청산(손절·익절)은 게이트 ①②와 무관하게 리스크 관리 차원에서 동작한다(단, kill-switch가 청산까지 막도록 설정 가능).

> 모의투자(VTS) 주의: KIS 모의환경은 **지수·거래량순위 조회를 미지원**할 수 있다. 이 경우
> 게이트 ①(코스피 MA)은 자동으로 **스킵**되거나, 데이터용 실전 크레덴셜이 있으면 그쪽으로 조회한다(아래 §5).

## 3. 표준 전략 = 진입/청산 신호

게이트를 통과한 종목에 대해 실제 매수/매도 타이밍을 만드는 규칙.

### 3.1 진입: 변동성 돌파 (Volatility Breakout)
래리 윌리엄스 변동성 돌파의 단순화 버전.

- 기준 변동폭 `R = 전일고가 - 전일저가`
- 돌파선 `target = 오늘시가 + k * R` (기본 `k = 0.5`)
- **현재가 ≥ target** 이면 매수 신호.

### 3.2 추세 필터 (역추세 방지)
- 종목 현재가가 **M일 이동평균(기본 5일) 위**일 때만 매수 허용.
- 하락 추세(MA 아래)에서는 돌파해도 진입하지 않는다.

### 3.3 분할매수 / 사이징
- 1회 주문액 `orderKrw`(기본 50만 원).
- 매수 수량 `qty = floor(orderKrw / 현재가)` (최소 1주).
- 단, 매수 후 종목 평가액이 **종목당 비중 한도**를 넘으면 그만큼 줄이거나 스킵.
- 같은 종목 같은 날 중복 매수는 1회로 제한(설정으로 분할 횟수 조정 가능).

### 3.4 청산: 익절 / 손절
- 보유 종목 수익률이 **+takeProfit%(기본 +5%)** 이상 → 전량 시장가 매도.
- 보유 종목 수익률이 **-stopLoss%(기본 -3%)** 이하 → 전량 시장가 매도(손절).
- (옵션) **종가 청산**: 장 마감 직전 사이클(예 15:15 이후)에 당일 진입분 전량 청산 — 오버나이트 리스크 회피.

### 3.5 주문 방식
- 기본 **시장가**(`ORD_DVSN: '01'`)로 체결 확실성 우선.
- 지정가(`'00'`) 옵션 제공(현재가 기준 오프셋).

## 5. 모의투자 데이터 한계 & 데이터 크레덴셜

KIS 모의(VTS, `openapivts...:29443`)는 **주문·잔고는 지원**하지만 **시세/지수/일봉 조회는 미지원**일 수 있다.
변동성 돌파·MA는 시세 데이터가 필수이므로 다음 중 하나로 해결한다.

1. **데이터 크레덴셜 분리(권장)**: 실전용 appkey/secret를 **데이터 조회 전용**으로 발급해
   `dataAppkey/dataSecret`에 넣는다. 시세·일봉·지수는 **실전 도메인**에서 읽고, 주문은 모의 도메인으로 보낸다.
   (실전 크레덴셜로 *조회만* 하므로 실거래 위험 없음)
2. **데이터 크레덴셜 미설정 시**: 워커가 모의 도메인으로 시세를 시도하고, 실패하면 해당 종목/게이트를
   **스킵**하고 로그에 사유를 남긴다(주문 안전). 코스피 MA 게이트(①)는 자동 스킵된다.

## 7. 전략 추천 (스캐너) — 워치리스트 후보 발굴

워치리스트는 거래 화이트리스트(이 종목만 매매)다. 채우는 일이 수동이면 결국 "감(感)"이
되므로, **부챙이 자신의 전략을 거꾸로 돌려** 후보를 발굴한다.

> 평소: `워치리스트(수동) → 전략 적용`
> 추천: `넓은 후보 유니버스 → 전략 점수화 → 통과분 추천 → 원클릭 워치리스트 추가`

**엔드포인트**: `GET /api/recommend` (관리 토큰 필요, 주문 없음 · 읽기전용).

**하이브리드 2단계**:
1. **정량 스크리너(싸고 결정론적)** — KIS 거래량/시총 순위로 후보 N개 수집 →
   종목당 **일봉 1회**만 조회(현재가=당일봉 종가)해 KIS 서브요청 절약 → 3단계 점수화:
   - **① 시장**: 코스피 MA 게이트(전 후보 공통, 1회 계산).
   - **② 추세·모멘텀**: 현재가 ≥ MA(`maPeriod`) 그리고 N일 모멘텀 ≥ 0. *(투챙이 '섹터 흐름' 자리를 부챙이가 가진 데이터로 치환 — 부챙이엔 섹터/펀더멘털 소스가 없음)*
   - **③ 변동성 셋업·유동성**: 양봉 + 돌파선(`open + k·R`) -3% 이내 + 유효 변동폭.
   - 점수 = GREEN 단계 수(0~3). 모두 GREEN이면 `매수`, 아니면 `관망`.
2. **정성 2차(Gemini, 선택)** — 정량 통과(≥2) 상위 `recommendShortlist`개만 Gemini에 보내
   단기 진입 관점 최종 판정(`매수`/`관망`) + 한 줄 사유를 받는다. `geminiApiKey` 미설정 시
   이 단계는 생략하고 **정량 점수만으로** 추천(기능은 그대로 동작).

**투챙이와의 관계**: 투챙이의 "3단계"는 실은 *Gemini + 거래량 순위*(정성)였다. 부챙이는
같은 UX(3단계 dot·매수/관망 카드)를 유지하되, 투챙이엔 없던 **정량 계산을 1차로** 두고
AI를 2차 보조로 돌리는 게 차이다 — 자동매매 봇이 실제로 쓰는 그 로직으로 후보를 고른다.

**한계/안전**: 후보 수는 KIS rate-limit·Worker 서브요청 한도 때문에 `recommendCount`(≤40)로
제한. 모의(VTS)는 순위/일봉 조회가 막힐 수 있어 데이터용 실전 키(§5) 권장. 추천은 **참고용**
이며, 워치리스트에 추가해도 dry-run·게이트·일일한도가 그대로 적용된다.

## 7-B. Tier 1 고도화 (리서치 기반, 2026-06-10)

리테일 자동매매 베스트프랙티스 리서치(ATR 스탑·트레일링·돌파 품질·백테스트) 반영. 모두 **기본 OFF**, dry-run 검증 후 켠다.

### 7-B.1 ATR 변동성 스탑 + 트레일링 스탑
- **ATR 손절**(`useAtrStop`): 손절선 = 진입가 − `atrStopMult`×ATR(`atrPeriod`). 고정 `stopLossPct` 대신 종목 변동성에 맞춰 폭을 정함. ATR 계산 불가 시 고정 %로 자동 폴백.
- **트레일링 스탑**(`useTrailingStop`): 보유 중 고점(`state.peak[ticker]`)을 추적, `고점 − trailAtrMult×ATR` 이탈 시 청산. `trailArmPct` 이상 수익 났을 때만 발동(수익 잠금). 익절(`takeProfitPct`)은 그대로 상단.
- 우선순위: 익절 → 트레일링 → (ATR 또는 고정)손절 → EOD청산.

### 7-B.2 돌파 품질 확인 (가짜 돌파 억제)
진입 신호에 추가 조건: `requireVolumeConfirm`(당일 거래량 ≥ `volMultiplier`×평균), `requireRangeExpansion`(당일 변동폭 ≥ 직전 ATR). 추천 스캐너 ③단계도 거래량비(`volRatio`) 반영.

### 7-B.3 경량 백테스터 — `POST /api/backtest`
워치리스트(또는 지정 종목)의 KIS 일봉에 현재 전략을 재생 → 종목별/집계 **승률·평균수익·총손익·MDD**. 진입=당일 돌파선 체결 가정, 청산=다음 봉부터(약식·일봉 근사). **자동 최적화는 의도적으로 미제공**(과최적화→실거래 실패 방지 — 리서치 공통 경고). 한계: KIS 일봉 endpoint가 ~30일만 줘서 히스토리 짧음(깊은 검증 아님, 방향성 점검용).

### 7-B.4 성과지표 추적
부챙이가 청산한 거래를 `state.trades`(최근 200개)에 누적 → `/api/status`가 승률·누적손익·MDD·최근거래 반환, 대시보드 표시. dry-run/실거래 분리 집계.

## 7-C. Tier 2 고도화 (2026-06-10)

리서치 기반 Tier 2(텔레그램 알림 제외). 모두 **기본 OFF**, dry-run 검증 후 켠다.

### 7-C.1 분할매수 / 분할익절
- **분할매수**(`entryTranches`): orderKrw를 N등분해 사이클마다 1트랜치씩 최대 N회 진입(state.tranches). `종목당 최대 비중`이 트랜치 합을 자연 제한 → N회를 다 못 채울 수 있음(안전). 1=단발(기존 동작).
- **분할익절**(`partialTpPct`>0): 보유 수익률이 partialTpPct 도달 시 `partialTpFraction`만큼 1회 부분매도, 잔량은 트레일링/풀익절로 계속(state.partialDone). takeProfitPct보다 작게 설정해야 의미.

### 7-C.2 regime 적응형 사이징 (`regimeSizing`, 라이브 전용)
코스피 vs MA 마진에 비례해 1회 매수액 축소: factor = clamp((코스피/MA−1)×100 / `regimeFullMarginPct`, `regimeMinFraction`, 1). 축소 전용(평소보다 더 사지 않음). 게이트① 코스피값 재사용(추가 KIS 호출 0). 데이터 없으면 `regimeFallbackFull`로 결정.

### 7-C.3 ADX 추세강도 필터 (`requireAdx`)
ADX(Wilder) ≥ `adxMin`일 때만 신규 진입(횡보장 가짜돌파 억제). 청산엔 미적용(진입 전용). 일봉 ~30봉 한계상 `adxPeriod`를 키우면 ADX 산출 불가→매수 멈출 수 있어 10~14 권장.

### 7-C.4 안전 거동 변경 (다단계 적대적 리뷰로 발견·수정)
- **청산은 일일 주문 한도로 막지 않는다**(구버전 버그 수정): 한도 도달 시에도 손절/익절/트레일링/EOD 매도는 항상 실행. 한도는 신규 매수에만 적용. *(기본값에서도 거동이 바뀜 — "한도 도달 후 청산까지 차단" 구거동은 손실 무한확대 위험이라 제거)*
- **dry-run도 dayOrders를 증가**시킨다(분할매수/부분익절 다주문의 한도 거동을 dry에서도 충실히 시뮬). `오늘 카운터 리셋`으로 초기화.
- **당일 재진입 금지**: 당일 매수→청산된 종목은 같은 날 재매수 안 함(손절 직후 재진입 방지).
- **stale 상태 prune**: 보유X+당일매수X 종목의 peak/tranches/partialDone를 매 사이클 정리(외부청산 잔재가 다음 lot 오염 방지).
- **중복 실행 방지 락**(best-effort KV): cron×수동 실행 겹침의 state lost-update 완화(완전 직렬화는 Durable Objects 필요).
- **잔고 페이지네이션**: 보유 종목이 한 페이지(~50)를 넘어도 전량 수집(prune 정확성).
- **백테스트**: ADX·분할익절 미러(같은 봉 손절 우선). 분할매수·regime은 라이브 전용(미반영).
- 검증: 순수 로직 단위테스트 24/24, 적대적 리뷰 2라운드 통과.
